# Concepts

- [Clean Code Notes](Technology/System%20Design/Concepts/Clean%20Code%20Notes.md) - A checklist of clean code rules covering naming, functions, comments, source structure, objects, tests, and common code smells.
- [Concurrency Parallelism And Multithreading](Technology/System%20Design/Concepts/Concurrency%20Parallelism%20And%20Multithreading.md) - Clarifies concurrency, parallelism, asynchronous execution, and multithreading, and explains why event-loop async beats threads for I/O-bound work.
- [Designing For Distributed Failure](Technology/System%20Design/Concepts/Designing%20For%20Distributed%20Failure.md) - How to design a multi-service system around failure: timeouts that mean unknown, partial failure, clock skew, replication lag, sagas and compensation, duplicate or out-of-order messages, retry budgets, tracing, and the trade-offs behind each choice.
- [Distributed Systems Problems](Technology/System%20Design/Concepts/Distributed%20Systems%20Problems.md) - Explains the core problems of distributed systems: partial failures, unreliable networks and clocks, synchronous versus asynchronous networks, and long-tail latency.
- [Modular Monolith Vs Microservices](Technology/System%20Design/Concepts/Modular%20Monolith%20Vs%20Microservices.md) - When a modular monolith is enough and when splitting into services pays off: boundary enforcement, in-process calls versus network calls, the Orders–Billing example, Spring Modulith and ArchUnit, and a Strangler Fig migration path.
- [Scaling Organizations](Technology/System%20Design/Concepts/Scaling%20Organizations.md) - Applies the Universal Scalability Law and Little's Law to scaling teams, with lessons on delegation, communication overhead, and limiting work in progress.
