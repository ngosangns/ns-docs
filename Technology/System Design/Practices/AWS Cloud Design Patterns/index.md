# Concepts

- [API Routing Hostname](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/API%20Routing%20Hostname.md) - Explains the hostname routing pattern, which isolates API services by giving each one its own hostname, with typical use cases and trade-offs.
- [API Routing HTTP](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/API%20Routing%20HTTP.md) - Explains the HTTP header routing pattern, where a request header selects the target service, action, version, or feature, along with its pros and cons.
- [API Routing Path](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/API%20Routing%20Path.md) - Explains the path routing pattern, which groups APIs under one hostname and separates services by URI, with NGINX, API Gateway, and CloudFront implementations on AWS.
- [Circuit Breaker](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/Circuit%20Breaker.md) - Describes the Circuit Breaker pattern, which stops a caller from repeatedly calling a failing or slow service, its three states, and how to build it on AWS.
- [Event Sourcing](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/Event%20Sourcing.md) - Describes the Event Sourcing pattern, which stores every state-changing event in an immutable event store and rebuilds state by replay, with challenges and AWS implementations.
- [Hexagonal Architecture](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/Hexagonal%20Architecture.md) - Describes the Hexagonal Architecture (Ports and Adapters) pattern for loosely coupled, independently testable applications, including how to apply it on AWS Lambda.
- [Retry With Backoff](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/Retry%20With%20Backoff.md) - Describes the Retry with Backoff pattern, which automatically retries operations that failed from transient errors using exponential backoff and jitter, with AWS implementations.
- [Saga Choreography](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/Saga%20Choreography.md) - Describes the Saga Choreography pattern, which keeps data consistent across services through event subscriptions instead of a central coordinator, with an AWS order-flow example.
- [Saga Orchestration](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/Saga%20Orchestration.md) - Describes the Saga Orchestration pattern, which uses a central orchestrator such as AWS Step Functions to coordinate distributed transactions and compensating actions.
- [Strangler Fig](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/Strangler%20Fig.md) - Describes the Strangler Fig pattern for incrementally migrating a monolith to microservices behind a proxy layer, with AWS implementations, benefits, and challenges.
- [Transactional Outbox](Technology/System%20Design/Practices/AWS%20Cloud%20Design%20Patterns/Transactional%20Outbox.md) - Describes the Transactional Outbox pattern, which solves the dual-write problem by saving events in the same transaction as the data, using an outbox table or change data capture.
