# Concepts

- [Ambassador Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Ambassador%20Pattern.md) - Explains how an ambassador helper service acts as an out-of-process proxy that sends network requests on behalf of a client, adding resiliency, routing, and security without changing the application.
- [Anti Corruption Layer Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Anti%20Corruption%20Layer%20Pattern.md) - Describes how a façade or adapter layer translates between subsystems with different semantics so a new application's design is not constrained by legacy or external systems.
- [Asynchronous Request Reply Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Asynchronous%20Request%20Reply%20Pattern.md) - Explains how to decouple long-running backend processing from the frontend using HTTP 202 and a polling status endpoint, with an Azure Functions implementation outline.
- [Backends For Frontends Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Backends%20For%20Frontends%20Pattern.md) - Describes creating a separate backend service per client interface so each frontend gets a tailored experience instead of forcing one shared backend to serve conflicting needs.
- [Bulkhead Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Bulkhead%20Pattern.md) - Explains how isolating application components into separate resource pools keeps a failure or overload in one pool from cascading, with a Kubernetes resource-limit example.
- [Cache Aside Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Cache%20Aside%20Pattern.md) - Explains how to load data into a cache on demand from a data store, and how to invalidate entries on update to keep the cache consistent, with a .NET example.
- [Choreography Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Choreography%20Pattern.md) - Describes decentralizing workflow logic across services that react to each other's events through a message broker, instead of relying on a central orchestrator.
- [Circuit Breaker Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Circuit%20Breaker%20Pattern.md) - Explains how a circuit-breaker proxy with Closed, Open, and Half-Open states stops an application from repeatedly calling a failing remote service and prevents cascading failures.
- [Claim Check Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Claim%20Check%20Pattern.md) - Explains how to move large payloads out of a messaging system by storing them externally and sending only a claim-check token, with Azure Blob Storage and Service Bus examples.
- [Cloud Design Patterns Index](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Cloud%20Design%20Patterns%20Index.md) - A catalog of Azure cloud design patterns with one-line summaries and the Well-Architected pillars each one supports, plus the distributed-computing fallacies they address.
- [Compensating Transaction Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Compensating%20Transaction%20Pattern.md) - Explains how to undo the steps of an eventually consistent, multi-step operation by running compensating actions instead of a traditional ACID rollback, with a travel-booking example.
- [Competing Consumers Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Competing%20Consumers%20Pattern.md) - Explains how multiple consumers can process messages from a single queue concurrently to improve throughput, scalability, and availability, including poison-message and idempotency concerns.
- [Compute Resource Consolidation Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Compute%20Resource%20Consolidation%20Pattern.md) - Describes consolidating multiple tasks into a single computational unit to raise resource utilization and cut cost, and the scalability, lifetime, security, and contention trade-offs involved.
- [CQRS Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/CQRS%20Pattern.md) - Covers Command Query Responsibility Segregation, which splits read and write operations into separate models to improve performance, scalability, and security.
- [Deployment Stamps Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Deployment%20Stamps%20Pattern.md) - Describes deploying multiple independent copies of a scale unit (stamps) to host different tenants, gaining near-linear scale, limited blast radius, and regional data placement.
- [Edge Workload Configuration Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Edge%20Workload%20Configuration%20Pattern.md) - Describes how to manage and distribute configuration to edge workloads that must keep running offline, comparing an external configuration controller with an internal configuration provider.
- [Event Sourcing Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Event%20Sourcing%20Pattern.md) - Explains storing every change to an entity as an immutable sequence of events in an append-only store, with materialized views, replay, snapshots, and trade-offs.
- [External Configuration Store Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/External%20Configuration%20Store%20Pattern.md) - Explains moving configuration out of the deployment package into a centralized store to avoid redeploys and share settings, with Azure App Configuration and Key Vault options.
- [Federated Identity Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Federated%20Identity%20Pattern.md) - Explains delegating authentication to an external identity provider using claims-based tokens for single sign-on, less admin overhead, and stronger security, with Microsoft Entra ID examples.
- [Gatekeeper Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Gatekeeper%20Pattern.md) - Explains protecting services with a dedicated, low-privilege broker that validates and sanitizes requests before handing them to a trusted host, shrinking the attack surface.
- [Gateway Aggregation Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Gateway%20Aggregation%20Pattern.md) - Explains using a gateway to combine multiple client requests into one, cutting chattiness and latency between clients and backend services.
- [Gateway Offloading Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Gateway%20Offloading%20Pattern.md) - Explains offloading shared cross-cutting functions such as SSL termination, authentication, and throttling to a gateway proxy so individual services stay simpler.
- [Gateway Routing Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Gateway%20Routing%20Pattern.md) - Explains routing requests to multiple services or service versions through a single layer-7 gateway endpoint, enabling backend abstraction and zero-downtime deployments.
- [Geode Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Geode%20Pattern.md) - Explains deploying self-contained backend nodes across geographic regions in an active-active setup so any node can serve any request, cutting latency and surviving regional outages.
- [Health Endpoint Monitoring Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Health%20Endpoint%20Monitoring%20Pattern.md) - Explains exposing application health-check endpoints that external monitoring tools poll to verify dependencies, response codes, and latency, plus security and caching considerations.
- [Index Table Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Index%20Table%20Pattern.md) - Explains emulating secondary indexes in NoSQL stores with separate index tables, comparing denormalized, normalized, and partially normalized layouts and their consistency costs.
- [Leader Election Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Leader%20Election%20Pattern.md) - Explains coordinating distributed instances by electing one leader via a distributed mutex or consensus algorithm, including heartbeat, lease, and failure considerations.
- [Materialized View Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Materialized%20View%20Pattern.md) - Explains generating prepopulated, read-only views over source data to speed up complex queries, with event-driven or scheduled refresh and eventual-consistency trade-offs.
- [Messaging Bridge Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Messaging%20Bridge%20Pattern.md) - Explains building a bridge component that relays messages between incompatible messaging infrastructures, such as MSMQ and Azure Service Bus, without changing existing systems.
- [Network Secure Ingress Implementation](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Network%20Secure%20Ingress%20Implementation.md) - Reference implementation that combines global routing, gateway offloading, and health endpoint monitoring to give HTTP/HTTPS applications a secure entry point on Azure.
- [Pipes And Filters Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Pipes%20And%20Filters%20Pattern.md) - Decompose a complex processing task into a chain of reusable, independently deployable and scalable filters connected by pipes.
- [Priority Queue Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Priority%20Queue%20Pattern.md) - Let a system process high-priority requests ahead of low-priority ones, using a priority-aware queue or separate queues per priority level.
- [Publisher Subscriber Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Publisher%20Subscriber%20Pattern.md) - Announce events to many interested consumers asynchronously through a message broker, without tightly coupling senders to receivers.
- [Quarantine Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Quarantine%20Pattern.md) - Validate third-party software artifacts in an isolated pipeline before they are trusted and released into the internal supply chain.
- [Queue Based Load Leveling Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Queue%20Based%20Load%20Leveling%20Pattern.md) - Place a queue between a task and the service it calls so the queue buffers intermittent heavy loads and smooths out peak demand.
- [Rate Limiting Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Rate%20Limiting%20Pattern.md) - Control resource consumption by capping the rate of access to a capacity-limited service, avoiding throttling errors and keeping throughput predictable.
- [Retry Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Retry%20Pattern.md) - Handle transient failures when connecting to services or network resources by transparently retrying failed operations, with backoff and idempotency in mind.
- [Saga Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Saga%20Pattern.md) - Keep data consistent across microservices with a sequence of local transactions and compensating transactions, using choreography or orchestration instead of two-phase commit.
- [Scheduler Agent Supervisor Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Scheduler%20Agent%20Supervisor%20Pattern.md) - Coordinate a set of distributed actions as a single operation, with a scheduler, agents, and a supervisor that recovers or compensates failed steps.
- [Sequential Convoy Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Sequential%20Convoy%20Pattern.md) - Process related messages in a defined order without blocking other message groups, using categories and message sessions to keep FIFO while scaling out.
- [Sharding Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Sharding%20Pattern.md) - Split a data store into horizontal partitions (shards) using lookup, range, or hash strategies to improve scalability and performance.
- [Sidecar Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Sidecar%20Pattern.md) - Deploy supporting components such as logging, monitoring, and proxies in a separate process or container attached to the main application, sharing its lifecycle.
- [Static Content Hosting Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Static%20Content%20Hosting%20Pattern.md) - Serve static assets from a cloud storage service, typically fronted by a CDN, instead of from application servers to cut cost and improve performance.
- [Strangler Fig Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Strangler%20Fig%20Pattern.md) - Incrementally migrate a legacy system by routing functionality through a façade and replacing it piece by piece with new services until the old system can be retired.
- [Throttling Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Throttling%20Pattern.md) - Control resource consumption per application instance, tenant, or service so the system keeps meeting its SLAs under sudden demand spikes.
- [Valet Key Pattern](Technology/System%20Design/Practices/Azure%20Design%20Patterns/Valet%20Key%20Pattern.md) - Give clients a short-lived, scoped token for direct access to a storage resource so data transfer bypasses the application server.
